# OpenBRC

Open source (GPL-3.0-or-later) reimplementation of *Barbie Riding Club* (Mattel Media /
Human Code, 1998) in modern C++. Goals, in priority order: the original game's behaviour,
then portability (Linux, Windows, macOS), then modern conveniences (any resolution, aspect
ratio and refresh rate, Vulkan with an OpenGL fallback).

## Hard rules

- **The original game is always required.** OpenBRC ships no game content. It reads
  everything from the user's disc image (ISO/BIN/CUE/IMG), the physical disc, or an
  existing installation, and refuses to start without one.
- **No game data in git.** Disc contents, extracted assets, RE databases, decompiler
  output and anything else derived from the retail files stay under the gitignored
  `local/` directory. Tests that need retail data read `$OPENBRC_GAME_DATA` and skip when
  it is unset.
- **Evidence, not invention.** Behaviour is reproduced from, in this order:
  1. The game executable (`Barbie Riding Club.exe` on the disc, SHA-256
     `74151dba…6c75`, MSVC 5, image base 0x400000). Analyse it with REA (the `rea` MCP
     tools, Ghidra provider) and the local Ghidra dump (`local/ghidra/brc_decomp.c`,
     regenerated by `local/ghidra/scripts/DumpDecomp.java`; `local/re/fn.py <addr>`
     prints one function). Port behaviour to readable C++ in this project's style: the
     same operation order and integer arithmetic, with the original function address
     cited in a comment (`// HCNode::Idle (0x44b1c0)`). Never paste decompiler output
     into the repository.
  2. The Open Media Toolkit 2.5 sources (LGPL-2.1, Yves Schmid; mirror in `local/omt`).
     The game links an older OMT 1.x, so formats and behaviour can differ; the
     executable wins. Code ported from OMT keeps an attribution comment.
  3. BarbieRecomp (`~/Projects/BarbieRecomp`, the maintainer's static recompilation of
     the same executable). Its `docs/api_usage.md` documents how the game uses every
     Win32/DirectX/Miles/Smacker API, with addresses. Its hand-written runtime (ISO
     reader, Smacker decoder, renderer, mixer) is the maintainer's own code and may be
     ported. Its `generated/` C is derived from the executable: documentation only.
     Running it (`build/barbie-riding-club --iso …`, `tools/autoplay.sh`) gives
     reference screenshots and behaviour to compare against.
- When behaviour is inferred rather than observed, say so in a comment and in the docs so
  it can be revisited.

## Layout

- `src/<module>/` — one static library `brc_<module>` per module; order and purpose are
  in `src/CMakeLists.txt`. Lower modules never depend on higher ones.
- `tests/<module>/test_*.cpp` — GoogleTest executables `test_<module>`.
- `tools/brctool/` — developer tool: list/extract/convert disc assets, run scenes.
- `docs/formats/*.md` — file formats, written as they are verified.
- `docs/engine/*.md` — how the original engine (OMT + Human Code "Godiva") behaves.
- `packaging/` — Windows installer (NSIS), Linux desktop files, macOS bundle.

## Conventions

- C++23, CMake ≥ 3.25, warning-clean on GCC, Clang and MSVC.
- Namespaces `brc::<module>`; files `PascalCase.cpp/.h`; members `m_name`.
- Formatting: `.clang-format` (4 spaces, 110 columns).
- Parsers take bytes (`std::span<const std::byte>` or `std::span<const uint8_t>`) and
  return `std::optional`/`std::expected` plus an error string; they never throw or abort
  on malformed input.
- OMT streams are big-endian (the toolkit came from the Mac); Smacker, WAV and BLIT
  payloads are little-endian.

## Building

```
cmake -S . -B build -G Ninja
cmake --build build
OPENBRC_GAME_DATA=~/Downloads/BRCV1_0.ISO ctest --test-dir build
./build/bin/openbrc --source ~/Downloads/BRCV1_0.ISO
```
